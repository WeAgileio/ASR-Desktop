# Design

## Context

動機與範圍見 proposal.md。既有 models.json 已保存完整資產、固定 revision、SHA-256 與下載量；ModelStore 負責校驗及離線快照。模型識別碼仍分散於 JobConfig、Adapter factory、desktop intake、offline loader 與 SwiftUI 選單。既有 ASRAdapter 的 session 介面可重用，Transcript 使用整數毫秒時間戳。

目前 desktop 的 local-model-management 尚在另一個未歸檔變更中。本設計保留其資產校驗與工作固定快照契約，不修改該變更的任務狀態。主規格的裝置條文與目前 auto 預設 CPU 的實作已有差異；本次只新增模型能力驗證，既有裝置政策不在範圍內。

## Goals / Non-Goals

**Goals:** 共用配置決定模型清單、引擎、裝置能力、資產與需求說明；兩個新模型先以 CPU 完成本機離線轉錄及字幕輸出；維持既有兩個模型與任務相容性。

**Non-Goals:** 遠端服務、自訂 Python 外掛、GUI 新增模型、模型格式轉換、GPU 路徑及效能最佳化。

## Decisions

### 共用登錄與明確引擎邊界

擴充現有模型配置，加入顯示名稱、引擎識別、主要元件、必要檔案、推論預設、支援裝置、熱詞能力與電腦需求資料。由共用登錄處理模型查詢及設定驗證，僅針對引擎保留 factory 分支。配置不能指定任意 Python import。相容引擎的新權重可登錄，未知引擎立即報錯。

比起任意外掛，此方案保留可預期的離線相依套件及打包範圍；比起單純新增模型名稱分支，可避免 GUI、CLI 與 worker 各自維護清單。

### 沿用各模型官方推論格式

Taiwan Tongues 使用 faster-whisper 載入官方 CTranslate2 權重；Breeze 使用 Transformers Whisper 載入官方 MediaTek-Research/Breeze-ASR-25 權重。先不轉換 Breeze 格式，以免引入額外轉換驗證。兩個引擎第一版只宣告 CPU；精度依 CPU 支援選擇並固定於配置。官方權重的實際下載 repository、revision 與完整必要檔案必須在配置生成時查證，不以 GitHub 專案頁當成權重來源。

### 固定資產與執行配置

新模型沿用明確準備、完整校驗及推論封鎖外連。資產快照以外，新增模型的引擎與辨識設定也須有穩定識別並保存於工作定義；worker 不從更新後的全域配置重建舊工作參數。快取包含相應識別，配置更新不能誤用舊結果。既有快照資料透過舊格式相容讀取保留。

### 統一結果、長音檔與錯誤

兩種 Adapter 使用 session 重用已載入模型，啟用各引擎的逐字／詞時間戳並轉為有界、排序的整數毫秒單位，讓既有字幕長度與時長設定可在詞邊界切分。不把句段時間戳宣稱為逐字精度，也不為缺失時間戳捏造平均分配。沿用長音檔分段與 checkpoint，驗證 Whisper 解碼長度與現有 chunk 大小相容，處理分段時間偏移。進度僅回報可觀測的完成區段，不虛構細粒度進度。缺失資產、記憶體不足與相依套件失敗須有可理解診斷。

### 模型頁需求資訊

模型選單依登錄動態產生；新模型的裝置選項只提供 auto 與 CPU。模型頁顯示平台、CPU、GPU 支援狀態、最低需求驗證狀態、記憶體建議與依據。下載量取自真實資產總和；準備空間沿用 ModelStore 的動態值。記憶體建議在沒有實測前標為估算，不能憑空給出已驗證最低 RAM。需求說明不作為硬體自動拒絕工作的門檻。

### 驗收與打包

更新 Python 相依套件、runtime lock 與 PyInstaller 的必要模組及原生函式庫。以單元測試驗證配置、能力拒絕、時間戳正規化與舊模型回歸；以兩個真實模型各完成短錄音 CPU 轉錄及 SRT，並於準備後封鎖外連重跑。效能只作觀察，不作通過門檻。原始碼測試不取代 frozen App 驗收。

## Risks / Trade-offs

- [模型下載與 CPU 載入成本高] → 顯示實際容量及估算記憶體建議；不預設下載所有模型。
- [兩個 runtime 增加打包複雜度] → 鎖定相依版本，驗證原生庫與 frozen runtime 的實際載入。
- [新模型不支援所有現有選項] → 共用能力驗證，GUI 限制選項，CLI 明確拒絕；熱詞不靜默忽略。
- [官方專案的附加後處理改變原文] → 僅整合必要模型推論，保留現有統一文字轉換與字幕流程，不搬入專案特定文字替換。
- [需求數值未充分量測] → 標示估算與未知最低值，實測紀錄保留執行環境及樣本範圍。

## Migration Plan

先新增相容登錄讀取與舊模型回歸測試，再加入新資產、引擎及 UI；更新 runtime 後執行模型與 App smoke。既有模型 ID、資產快照與工作資料保持可讀；不在轉錄時安裝相依套件或下載權重。若需回復，停用新模型登錄但保留已接受工作的固定定義，避免破壞歷史及輸出。
