# Design

## Context

動機見 proposal.md。現有 App 使用 macOS 14+ SwiftUI，四分頁與 DesktopModel 集中於 `desktop/Sources/ASRDesktopApp/DesktopView.swift`，更新設定另有 `UpdateSettingsView.swift`。服務已提供批次、完整範圍查詢、選取快照、模型與任務狀態，本案先改善呈現與 App 層狀態，不擴充服務協定。

### Evidence

以下為 2026-10-25 讀取原始碼後的審查，並非實機測試結果。電腦上的 ASR Desktop 當時未執行，未啟動背景工作來取得畫面；已安裝版本也未核對是否與目前原始碼相同。

| 優先 | 已確認的程式證據 | 使用者影響與判斷 |
| --- | --- | --- |
| P1 | `DesktopModel.submit()` 成功後固定提示按「恢復佇列」 | 佇列運作中仍出現錯誤指引，可直接由分支邏輯確認 |
| P1 | `outputOptions` 在匯入與設定共用同一組 model 欄位；`options` 亦包含語言、字幕、覆寫等設定頁欄位 | 切頁修改會改動同一份提交選項，作用範圍不清楚 |
| P1 | `submit()` 不要求 preview；預覽失效僅涵蓋部分選項，`inspect()` 沒有輸入世代檢查 | 使用者可略過預覽，或看到與目前輸入不一致的舊計畫；服務仍重新驗證，不能推論成檔案安全已失守 |
| P1 | `paused` 初值 true、`compatible` 初值 false；標頭只讀 paused，連線失敗只寫 message | 連線未完成也呈現確定的暫停狀態；無法辨識服務與佇列的不同問題 |
| P1 | `jobsView` 三欄 minWidth 為 180／300／300；視窗 minWidth 860，外層還有 padding | 最小寬度餘裕有限；長檔名、按鈕擠壓與裁切屬待實機驗證風險，尚未重現 |
| P1 | 詳情同時提供取消、重試、移除；未根據狀態停用。勾選為空字串 Toggle 並隱藏 label | 可能讓使用者嘗試不適用動作；輔助使用名稱不足，實際朗讀仍待驗證 |
| P2 | 全域 message 底部 lineLimit(2)，一般成功寫「操作已接受」，輪詢亦可改寫 message | 長錯誤缺乏完整呈現入口，難以判斷結果屬於哪個動作 |
| P2 | 批次改名、重試失敗、整批移除僅在 contextMenu；查詢篩選只顯示狀態個數 | 功能可發現性與條件辨識成本偏高，應提供可見入口 |
| P2 | 任務列只有檔名、state、duration；進度與成果集中在長詳情 | 多任務監看需反覆開啟詳情，成果入口層級可提高 |
| P2 | 匯入同一 List 先顯示 sources 根路徑再顯示 inspection；模型卡先列多行硬體說明，所有狀態皆有下載／修復、驗證、移除 | 匯入容易看似重複；模型狀態對應的下一步不突出 |

既有優點應保留：原生控制項、來源與成果 Finder 定位、真實／估計進度區分、模型大小與空間資訊、移除紀錄前的明確確認、常駐品牌與版本，以及跨頁查詢世代保護。現有 SelectionTests 已涵蓋換頁保留選取、變更條件清除選取，須保留。

### Guidance

使用 ui-ux-pro-max 的 SwiftUI 搜尋取得輔助使用名稱與 FocusState 建議，UX 搜尋取得就地錯誤與可修正下一步建議。整體 design-system 查詢卻匹配到網站行銷頁的 Product Demo + Features；本案判定不適用，不採用其版型、配色與網頁字型，也未持久化該結果。原生 Mac 的方向參考 [Apple Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/) 與 [Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)：視窗可調整、鍵盤與選單可達、主要工具易發現。技能中的手機 44pt 觸控規則不直接套用桌面控制項。

## Goals / Non-Goals

**Goals:**
- 使用者在每一步都能理解目前狀態、動作範圍及下一步，依兩份 delta specs 驗收。
- 在既有 860×640 最小視窗內保持可操作，預設與較大視窗提高監看效率。
- 僅新增本次行為需要的 View 與狀態；原生系統字型、語意色與 SF Symbols 維持一致。

**Non-Goals:**
- 不做全站側欄重建、視覺品牌換裝或全域設計系統框架。
- 不重寫 DesktopCore／後端，不改變服務的排程、檔案驗證、移除與安全重送契約。
- 不把本次設計判斷描述成經使用者研究驗證的需求；本案是依程式證據提出的改善基線。

## Decisions

### 1. 保留四分頁，以任務區自適應解決空間

不把模型、設定一起移到常駐側欄，以免和任務頁批次側欄形成雙重導覽。保留匯入、任務、模型、設定；以綁定的分頁狀態支援提交後與模型提示的跨頁入口。

任務頁可用內容寬度達約 1000 點時使用批次／列表／詳情三欄；較窄時改為批次／列表兩欄，查看詳情在內容區切換並提供「返回任務」；批次切換入口仍可達。1000 點是初始配置值，須以真實文字量驗證後調整；不是規格鎖定的產品行為。

寬版概念配置（下圖為設計示意，並非現有畫面）：

```text
+--------------------------------------------------------------------+
| ASR Desktop                 Service: Ready | Queue: Paused [Resume] |
| [Import] [Jobs] [Models] [Settings]                                 |
+-----------------+----------------------------+---------------------+
| Batches         | Scope / Search / Filters   | File / State        |
| All jobs        | Counts + [Batch actions]   | Progress or Error   |
| * Interview     | Selection: 3 [Actions]     | Delivered outputs   |
|   Meeting       | [x] file-a  Running phase  | [Reveal in Finder]  |
|                 | [x] file-b  Failed         | Source / Settings   |
|                 | [x] file-c  Completed      | [More details]      |
|                 | Page range                 |                     |
+-----------------+----------------------------+---------------------+
| Short contextual status                  Version | karakuri.tech   |
+--------------------------------------------------------------------+
```

窄版只替換列表／詳情呈現，不建立第二份查詢或選取狀態。查看任務 ID 與批次勾選集合分離：前者有目前項目 highlight，後者使用有檔名標籤的 checkbox。若沿用手動勾選，從全選快照改為單筆勾選時要明示範圍變更，保留現有服務快照與確認檢查。

### 2. 匯入使用三區與可核對的預覽

來源區提供選檔、拖入、清除與遞迴控制，根來源以摘要呈現；媒體清單逐列顯示檔名、可查看的完整路徑、時長與驗證結果。避免根路徑與展開媒體看似兩份任務。輸出區先呈現輸出目錄、格式、模型與文字選項，裝置與語言、熱詞、字幕限制、覆寫等進階選項可展開，所有作用於提交的值都能確認。

預覽成功後顯示有效／無效數與輸出計畫，再啟用「提交 N 個有效檔案」。本案選擇要求目前預覽，替代現行可直接提交：增加一次確認但讓「提交有效檔案」的範圍事先可見。這是明確的提案行為改變，並非宣稱原本已要求預覽。

預覽綁定完整 submission 輸入快照／世代；任一來源、遞迴、輸出路徑或 options 值變更即失效，遲到回應不能覆蓋新狀態。提交仍由服務重新驗證，不把預覽視為保證檔案未改變。缺模型允許排入 blocked，預覽與提交前說明即可，不自行下載。

```text
Sources + Output + Options --> Preview current input --> Confirm valid files
           ^                         |                         |
           +----- edit invalidates --+                         v
                                              Accepted batch + [View batch]
                                                     |
                                      +--------------+---------------+
                                      v              v               v
                                  Queue paused   Queue active    Model missing
                                  [Resume]       Waiting/running [Prepare model]
```

提交成功保留 batch_id，提供查看該批次，不強制切頁或宣稱已開始。文字以刷新後狀態為準；刷新失敗時保留已接受結果並標示狀態待確認。匯入提交期間凍結該份輸入，避免成功清空使用者在等待期間新增的來源；失敗保留輸入，允許修正。

### 3. 分離匯入草稿與設定草稿

最少分成已儲存預設值快照、設定頁草稿、本次匯入草稿。設定保存只更新已儲存快照與該設定草稿；匯入提供明確的「套用已儲存預設值」。新匯入草稿由最近已確認的預設值初始化；若還未載入服務預設值，保留可見的載入狀態，不把佔位值當成已儲存。

外部更新時，乾淨的設定草稿可同步；有本地修改則保留並提示重新載入，匯入草稿不跟隨輪詢覆寫。避免以一組雙向 Binding 隱式共享兩頁編輯，亦不建立全域複雜的表單框架。

設定頁分組順序：新任務預設值（含儲存／還原及未儲存提示）、裝置與校準、背景服務與診斷、App 版本與更新、CLI 工具。版本與更新功能仍完整保留；校準依舊由使用者選樣本並明確啟動。

### 4. 區域回饋與服務狀態分離

App 層保存連線中、可用、無法連線、能力不相容等狀態；queue paused 只在有成功狀態資料時解讀，舊資料須標示。連線／刷新失敗不以初值 true 顯示為確定暫停，也不因使用者僅看畫面而自動恢復服務或工作。

將操作結果按匯入、任務、模型、設定各區保存最近一筆，含操作名稱、成功／失敗／未確認、訊息與下一步；不建立長期活動紀錄。完整訊息在原區域可展開及選取，底部只作短摘要。輪詢錯誤與使用者操作結果分開；待處理錯誤不被一般刷新覆蓋。

沿用 PendingCommand 的相同請求確認機制，未確認期間可讀取及導覽，但衝突的變更控制不可觸發。避免用「再試一次」產生新請求來繞過 pending，也不把傳送成功當成背景工作完成。

### 5. 狀態優先的任務與模型動作

任務列補目前階段與有效進度；數值、估計標示與 ETA 沿用服務欄位，沒有資料時只顯示處理中。詳情依「狀態與下一步 → 已交付成果 → 來源與設定 → 進階資訊」排序；以已交付且存在的路徑支援 Finder，部分成功與遺失成果分開顯示。

| 任務狀態 | 可提供主要動作 | 不適用動作 |
| --- | --- | --- |
| queued／blocked | 取消；blocked 可前往指定模型 | 重試 |
| running | 取消 | 重試、移除 |
| cancelling／未回收 | 顯示等待停止 | 重複取消、重試、移除 |
| failed／cancelled／已回收 interrupted | 重試，查看部分成果 | 取消 |
| completed | 查看成果 | 取消、重試 |

移除仍依服務 selection preview 與 target_token 確認，UI 的停用只是減少誤操作。批次動作另有可見的 Menu，破壞性操作保留既有確認視窗；選取列僅在有勾選時展開，避免沒有選取時常駐整排無效按鈕。

模型卡先呈現名稱、狀態、大小、準備動作：missing 下載、downloading／verifying 顯示進度、失敗修復、ready 已就緒；驗證／移除為次要動作。硬體需求可展開，仍在啟動下載前可取得所有大小與空間資訊。移除須確認實際模型與空間影響，並由既有服務拒絕引用衝突。

### 6. 原生視覺與無障礙基線

系統字型與語意文字層級、系統背景、分隔線、原生選取色與 SF Symbols 為基線；不導入網頁字型或任意新色盤。主要動作使用 prominent，其餘保留 secondary；同區同層級使用一致間距，長路徑可換行／查看全文，不以縮到不可讀來容納。

Cmd+O 提供匯入檔案入口、Cmd+F 在任務頁聚焦搜尋，對應選單可發現；不為提交或刪除配置容易誤觸的全域單鍵。使用原生焦點管理，對話框 Escape 取消、非破壞性儲存提供預設動作，關閉後回到發起控制項。選取 checkbox 的輔助使用名稱含檔名，錯誤可被讀取且只在操作事件改變時公告，2 秒輪詢不反覆公告進度。減少動態效果時不依賴動畫。

## Risks / Trade-offs

- [要求預覽多一次操作] → 換取可確認的檔案數與輸出計畫；顯示未完成條件，避免使用者猜測按鈕為何停用。
- [窄版切換詳情會降低同屏監看量] → 保留列表階段與成果摘要、返回時恢復相同查詢與選取；寬版仍保留三欄。
- [畫面操作與服務狀態之間可能競爭] → 服務仍是權威，拒絕後就地顯示並刷新；不依賴 UI 停用當成安全檢查。
- [獨立草稿可能讓使用者期待保存後立即套用] → 明示作用範圍並提供明確套用入口，不靜默同步。
- [尚未核對像素、AX 行為與長文字配置] → 實作時以最小／預設／寬視窗、雙外觀、長中文／英文檔名、VoiceOver 與鍵盤實測；本輪不聲稱已通過。

## Migration Plan

不變更持久化格式。先完成 App 層草稿、預覽與回饋狀態，再改組畫面，最後做情境驗收。沿用既有偏好與服務設定，不修改已接受任務快照。若回退 App 介面版本，後端與 CLI 不需資料遷移；尚未提交的畫面草稿不承諾跨版本保存。
