# Spec Delta

## Purpose

讓桌面使用者得知本專案 GitHub 上較新且可下載的相容 App 版本，清楚區分版本通道與檢查失敗，保留稍後提醒、略過及自行安裝的選擇，並讓更新檢查不影響本機轉錄工作與資料。

## ADDED Requirements

### Requirement: 常駐顯示目前 App 版本

主視窗 SHALL 在各分頁共用的底部區域顯示目前執行的 App 完整版本，設定頁亦 SHALL 顯示同一版本；預發布版須保留 beta 及序號，不以遠端候選版本替代。目前版本 SHALL 從本機 App 取得，不依賴網路、更新檢查或背景服務；缺失或無法辨識時明示版本未知，不虛構數值。

#### Scenario: 開啟與切換分頁
- **WHEN** 使用者開啟版本為 `0.2.0b2` 的 App 並切換匯入、任務、模型或設定頁
- **THEN** 底部持續顯示 `v0.2.0-beta.2`，設定頁呈現相同完整版本，在支援的最小視窗尺寸仍可讀

#### Scenario: 離線或背景服務未連線
- **WHEN** App 離線、停用自動檢查或背景服務尚未連線
- **THEN** 已安裝版本仍立即可見，無須等待檢查更新成功

#### Scenario: 遠端版本不同或本機版本缺失
- **WHEN** 發現較新 Release 或本機缺少有效版本資訊
- **THEN** 較新 Release 只標為可用更新，不改寫目前版本標示；本機無有效資訊時顯示「版本未知」

### Requirement: 依可安裝版本判定更新

系統 SHALL 從指定的本專案 GitHub Release 清單選出版本最高且比目前 App 更新的相容版本，排除草稿、無法辨識的版本及沒有符合平台 DMG 的 Release。版本 SHALL 依數值及預發布順序比較，不以字串、建立日期或清單位置代替；清單未完整取得時不得宣稱已是最新版。

#### Scenario: 測試版格式與數值比較
- **WHEN** App 為 `0.2.0b2`，Release 有 `v0.2.0-beta.2`、`v0.2.0-beta.10` 及 `v0.2.0`
- **THEN** 前者視為目前版本，beta.10 較新而正式版最高；相容資產齊備時選擇正式版

#### Scenario: 正式與測試通道
- **WHEN** App 為正式版或 beta 版並檢查更新
- **THEN** 正式版只接收 tag 與 Release 標記一致的正式版，beta 版可接收較新的 beta 與正式版，均不得推薦降級

#### Scenario: 最新 Release 沒有安裝包
- **WHEN** 較新 Release 只有原始碼壓縮檔或不符合本機平台的附件
- **THEN** 該版不成為更新候選；其他頁面若有較新且相容的版本仍可被選中，沒有候選時顯示沒有可用更新

#### Scenario: 沒有 Release 或版本無法辨識
- **WHEN** 成功取得空 Release 清單，或目前 App 缺少可辨識的完整版本
- **THEN** 前者顯示目前沒有可下載版本，後者說明無法判斷更新，不猜測版本或顯示已是最新版

### Requirement: 提供背景與手動檢查

系統 SHALL 在啟動後以非阻塞方式檢查更新，預設啟用且可關閉自動檢查，距上次自動嘗試至少 24 小時才再次自動檢查。設定頁 SHALL 提供手動檢查、目前版本、最後成功檢查時間及檢查結果；重複操作不得產生競爭回應或多個相同提醒。

#### Scenario: 同一天重開 App
- **WHEN** 上次自動檢查嘗試尚未滿 24 小時而使用者重開 App
- **THEN** 不再次自動連線，手動檢查仍可執行；停用自動檢查後重開亦維持停用

#### Scenario: 手動檢查及重複點擊
- **WHEN** 使用者手動檢查且連續點擊檢查按鈕
- **THEN** 顯示單一進行中狀態，結果只反映有效請求，並遵守伺服器要求的重試等待時間

### Requirement: 尊重提醒選擇並交接下載頁

發現更新時系統 SHALL 顯示目前版本、候選版本、版本通道與更新說明，提供前往下載、稍後提醒及略過此版本。前往下載 SHALL 僅以預設瀏覽器開啟該候選版本的本專案 HTTPS Release 頁，無法開啟時明確提示；不得自動下載安裝、停止背景服務或更動任務與模型。

#### Scenario: 使用者選擇前往下載
- **WHEN** 使用者在新版提醒選擇前往下載
- **THEN** 開啟該版 Release 頁而非泛用最新版本頁，使用者自行選擇下載與安裝，轉錄工作繼續

#### Scenario: 稍後與略過
- **WHEN** 使用者選擇稍後提醒或略過此版本
- **THEN** 稍後在下次符合自動檢查條件時才可再提示；略過在重啟後仍抑制該版本自動提醒，但較新版本不受影響，手動檢查仍可顯示被略過的候選

#### Scenario: 說明缺失或連結不可信
- **WHEN** Release 沒有更新說明，或回傳的下載頁不是指定儲存庫的 HTTPS Release 頁
- **THEN** 說明缺失時顯示未提供說明；不可信連結不被開啟，也不改用任意外部頁面

### Requirement: 檢查失敗不影響工作或洩露資料

系統 SHALL 區分檢查中、可更新、沒有可用更新及失敗，處理離線、逾時、限流、回應格式錯誤及權限／儲存庫錯誤。背景失敗不得彈出反覆阻斷工作的視窗，也不得覆寫最後成功時間或冒充已是最新版。請求 SHALL 僅取得公開發布資料，不攜帶音訊、本機路徑、任務、模型資料或內嵌憑證。

#### Scenario: 網路失敗或 API 限流
- **WHEN** 檢查收到逾時、403／429 限流或無效資料
- **THEN** 設定頁可查看失敗原因與適當的重試方式，保留上次成功紀錄並標示非最新結果，轉錄與本機管理仍可用

#### Scenario: 檢查期間轉錄
- **WHEN** 背景檢查執行且轉錄任務正在進行
- **THEN** 不改變佇列、服務及任務狀態，亦不將本機轉錄資料送往 GitHub
