# Spec Delta

## Purpose

讓維護者透過 GitHub Actions 為指定的既有桌面版本建立或補齊可下載的 DMG 與校驗檔，確保資產對應正確標籤來源、保留既有發布內容，並能辨認重跑與失敗結果，供桌面更新提醒提供可靠下載入口。

## ADDED Requirements

### Requirement: 明確選擇只建置或補包

發布流程 SHALL 保留既有 beta 標籤推送建置發布與手動只建置模式，並提供需要明確選擇的手動補包模式。補包 SHALL 要求既有版本標籤，不能從分支名猜測版本或自動建立／移動標籤；未選擇補包的手動執行不得修改 GitHub Release。

#### Scenario: 手動只建置
- **WHEN** 維護者以預設手動模式執行工作流程
- **THEN** 產生驗證過的建置 Artifact 與報告，不建立 Release 或上傳 Release 資產

#### Scenario: 指定標籤補包
- **WHEN** 維護者選擇補包並提供有效的既有 beta 標籤
- **THEN** 流程針對該版本建置／核對缺少的資產，不把工作流程所在分支當成目標版本

### Requirement: 安裝包與標籤來源一致

補包流程 SHALL 使用指定 annotated tag 指向的程式碼，核對 tag、來源版本、App 完整版本與該版更新說明一致，並在發布前再次確認標籤未改變。僅支援現有 Apple Silicon／macOS 14 以上 beta ad-hoc 打包契約；不符合條件、缺少必要來源或無法建置的舊版 SHALL 明確失敗，不以新程式替代。

#### Scenario: 標籤或版本不符
- **WHEN** 標籤不存在、不是 annotated tag、版本不符、不是支援的 beta 格式或缺少版本說明
- **THEN** 停止發布並指出原因，不新增或覆寫任何 Release 資產

#### Scenario: 建置期間標籤改變
- **WHEN** 發布前解析出的標籤提交與建置時記錄不同
- **THEN** 拒絕上傳，不把已建置的安裝包附到不同來源的版本

### Requirement: 驗證通過才提供安裝資產

新建置的安裝包 SHALL 通過相關原生／Python 測試、runtime／媒體工具及 DMG 驗證，並產生與實際 DMG 位元組一致的 SHA-256 校驗檔。發布權限 SHALL 僅提供給需要發布的步驟；建置或驗證失敗不得宣稱可安裝版本已發布。

#### Scenario: 驗證失敗
- **WHEN** 測試、封裝、DMG 或校驗驗證任一失敗
- **THEN** 不進行新資產發布，保留可用診斷報告並標示失敗

#### Scenario: 產物驗證完成
- **WHEN** 目標 beta 版本成功通過建置與驗證
- **THEN** 提供帶版本與 arm64 標示的 DMG、對應 SHA-256 檔及來源標籤／提交與驗證摘要

### Requirement: 補齊資產而不覆寫既有發布

Release 不存在時，流程 SHALL 依標籤與該版更新說明建立 Prerelease；已存在時 SHALL 保留標題、說明、草稿／預發布狀態與其他資產，只補缺少的預期檔案。既有同名資產不得被靜默覆寫或刪除；草稿不得因補包而自動公開。

#### Scenario: 沒有 Release 或沒有 DMG
- **WHEN** 目標 Release 不存在，或已存在但缺少預期 DMG
- **THEN** 驗證完成後建立 Release 或補上 DMG 及缺少的校驗檔；若已有校驗檔，必須與將上傳的 DMG 一致才可補包

#### Scenario: 只缺校驗檔
- **WHEN** Release 已有完整可下載的預期 DMG，但沒有對應 SHA-256 檔
- **THEN** 下載既有 DMG 並驗證其版本及封裝有效性，依該檔實際位元組產生校驗檔，不用重新建置的不同位元組為既有 DMG 背書

#### Scenario: 資產齊全或衝突
- **WHEN** DMG 與校驗檔已存在且一致，或校驗不符／同名資產異常
- **THEN** 前者回報已齊全而不重複上傳；後者停止並回報衝突，要求維護者另外處理

### Requirement: 發布結果可核對並可重跑

同一標籤的發布與補包 SHALL 避免相互覆寫，完成後重新讀取目標 Release 與資產，核對預期檔案、校驗及來源資訊並提供 Release 連結。部分上傳失敗 SHALL 回報已完成及缺少的項目；重跑不得建立重複 Release 或破壞已成功資產。

#### Scenario: 上傳中斷後重跑
- **WHEN** DMG 已上傳但校驗檔上傳失敗，維護者重新執行補包
- **THEN** 辨認已存在的 DMG，驗證後補齊校驗檔並核對最終結果，不再次替換 DMG

#### Scenario: 同標籤競爭
- **WHEN** 標籤發布與手動補包同時處理同一版本
- **THEN** 流程序列化或偵測衝突後重新讀取已存在資產，不使用強制覆寫來掩蓋競爭
